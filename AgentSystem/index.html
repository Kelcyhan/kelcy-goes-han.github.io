From context transfer to artifact colocation.

The page is shaped around the paper's central claim: the workspace is not passive storage. It is the coupling mechanism between researcher, agents, and material representations. Agent System therefore treats files, chats, approvals, and briefings as one activity-centered workspace.

Four design principles shaped the interface.

The earlier design notes called for a calm, dense, operational cockpit. The paper explains why: when agents work across many sessions, the interface has to preserve context, expose attention points, and keep artifacts inspectable.

01 / colocation

Artifacts stay attached to the work.

Documents, notes, code, data, screenshots, papers, and prior outputs remain addressable in the task structure, so an agent can use the same material the human sees.

02 / continuity

Sessions leave receipts, not mystery.

Each agent run produces a receipt: what happened, what changed, and what remains unresolved. Briefings synthesize receipts into the next working state.

03 / oversight

Human attention is calibrated.

Full, light, and auto oversight let routine work move quickly while strategic framing, approvals, and redirects remain visible and interruptible.

04 / density

The UI favors scanning over spectacle.

Status dots, queue items, tabs, file chips, and compact cards answer three questions: what is happening, what needs attention, and where to continue.

The cockpit grammar is deliberately quiet.

The product should not feel like a marketing dashboard. It should feel like a workbench: stable shell, persistent project context, fast inspection, and no decorative layer that competes with the work.

What is happening now?

Live agent rows, status dots, progress blocks, and session metadata surface movement without requiring the user to open every thread.

What needs my attention?

Approval queue items and blocked states are treated as steering points, not notifications to dismiss.

Where can I inspect or continue?

Project cards, task nodes, file chips, and docked tabs preserve return paths to the exact artifact or session.

Operational layout grammar cards / panels / tabs / queue

Status is semantic

Active, attention, complete, and inactive colors are shared across tasks, agents, and sessions.

Cards are objects

A project card or queue item represents something inspectable, not a decorative container.

Panels are structure

The app shell stays stable while task, chat, and document surfaces change inside it.

Chat is workspace

Tool traces and file references remain compact, expandable, and connected to artifacts.

A morning in the system.

The interaction model comes from the paper scenario: a researcher returns to accumulated project state, asks for one instruction over already-present artifacts, reviews linked outputs, and steers the next move.

08:40 briefing

Read yesterday's synthesis.

Chainlink has condensed session receipts into open loops, completed work, and suggested next focus.

09:05 instruction

Ask once, with context present.

The task agent opens the draft, prior analysis, and newly ingested papers from the shared workspace.

09:35 approval

Review the plan at the artifact level.

The researcher approves, redirects, or dismisses based on linked files rather than reconstructed chat history.

10:10 continuity

Leave a receipt for later.

The session writes what changed and what remains, turning today's work into tomorrow's starting context.

Research synthesis

Not more magic. Better working conditions.

The deployment finding was not that agents became inherently smarter. The workspace changed what their capabilities could attach to: persistent artifacts, linked approvals, and cross-session memory.

Colocation reduced routine context transfer.

Relevant papers, notes, code, and prior outputs were already present, so work began from shared state instead of prompt reconstruction.

The researcher's role shifted to steering.

Approval interactions became active decision points for directing attention, not clerical steps for moving information between apps.

The filesystem became shared state.

No separate agent memory database was required; ordinary files were the durable coordination mechanism.

mechanism 01
Ordinary files become coordination objects.

Research artifacts are not exported into the AI layer; agents operate where the work already lives.

mechanism 02
Receipts make sessions inspectable.

Each run leaves a structured account of decisions, changes, and unresolved loops.

mechanism 03
Approvals become steering moments.

The queue is designed for redirection and judgment, not passive notification.

mechanism 04
Briefings compress time.

Later work resumes from accumulated project state instead of from a blank prompt.
