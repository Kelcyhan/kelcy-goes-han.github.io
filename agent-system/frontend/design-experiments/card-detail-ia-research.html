Card detail page 应该成为“对象工作台”，不是一个更大的卡片

现在系统已经有 project/domain/task/card、agent workspace、files、plan/log、goals widget 和右侧 queue。 因此详情页的职责应该是：展示当前对象的 contract、执行证据、相关资源，以及进入 agent workspace 的清晰入口。

展示原则IA

1. Header 只放识别和高频操作

标题、状态、路径、spawn agent、move/archive/delete 适合常驻。不要在 header 堆完整 metadata。

2. Contract 要比 raw context 更靠上

用户进入卡片首先想知道“这件事完成标准是什么”，所以 objective/done_when/deps 应该比文件列表更早出现。

3. Agents 和 Files 是首屏双主区

这两个区域直接决定“谁在做”和“产物在哪里”，不应该被压进一个窄边栏或互相抢空间。

4. Agent workspace 不复制，只给入口和摘要

详情页显示 active/past agent 的状态、glance、文件变更；完整对话和终端留给 agent workspace。

基于当前系统的信息展示建议Summary
信息
现在系统中哪里有
详情页如何展示
title / status / desc
NodeDetail + updateTaskFields / renameTask
常驻 header；title 和 desc inline edit，status 用 dropdown。
objective / outcome / done_when
task.md YAML fields
done_when 作为顶部进度；objective/outcome 放 evidence drawer 或 contract panel。
deps / open questions / priorities
NodeHeader 已有编辑器
作为“risk/context”而不是散落 chip；空时隐藏或轻提示。
children / archived children
fetchChildren + ChildCardGrid
主画布；支持 drag reorder、move into、move to parent、archive bucket。
active / past agents
NodeAgentsPanel + sessionCards
首屏大面板；展示摘要、操作和入口；完整聊天进入 agent workspace。
files / artifacts
FileColumn + vault APIs
首屏大面板；支持 create/upload/rename/delete/move/download/preview。
plan / log
worklog.md parsed by fetchPlan/fetchLog
底部 evidence drawer；plan 可 toggle，log 负责 resume brief 和 change history。
goals
goals state + Goals widget
详情页只显示 goal tag/link；完整 goal 视图仍属于 widget / goals workspace。
结论：详情页应该保留所有原系统可容纳的信息，但不要平均铺开。高频识别和操作放 header；对象 contract 放 brief strip； agents 和 files 是首屏双主区；children/context 是第二层工作区；plan/log/outcome/references 是 evidence drawer。 这样既保留原有 operators，又不会把页面变成一个很长的字段表。
