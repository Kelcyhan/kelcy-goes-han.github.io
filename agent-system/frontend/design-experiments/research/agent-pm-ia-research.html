Agent + Project Management IA Research

让 Agent 会话常驻系统，但不要占用项目管理的注意力主舞台

这份调研把 Linear、Jira、ClickUp、GitHub Copilot agent 的交互模式拆成信息架构原则，并针对当前 PM 面板的右侧上下文栏与 session rail 给出一个低负担方案：右侧栏做“对象检查器”，session rail 做“环境状态层”，完整会话进入抽屉或详情页。

研究对象：agent sessions、project hierarchy、right inspector 输出：信息架构图、放置策略、界面线框 日期：2026-06-19
结论 双入口 工具模式 IA 原则 右侧栏诊断 Session Rail 推荐方案 来源

核心结论

Agent 会话不应该变成 PM 系统里的另一套项目层级。它更像“正在替你工作的参与者”和“需要你处理的事件流”。

Recommendation
1
项目层级是归档骨架，不是唯一入口

Project / Domain / Task 决定上下文、权限和进度，但用户不应该每次都先钻树才能找 agent 聊天。

2
右侧栏只回答“当前对象是什么”

右侧上下文栏应聚焦选中任务的 brief、资源、证据、活动。Agent 只显示与该对象有关的摘要和入口。

3
Session rail 同时是快速聊天入口

常驻态显示最近和活跃会话；点击即可继续 chat / agent。层级归类放在展开态和详情中，而不是挡住直接交互。

修正：需要“双主入口”

你的担心是对的：如果只强调项目树，用户会失去和 chat/agent 直接交互的速度。更合理的是两套入口并存：Agent Dock 负责“现在我要找谁聊/谁在工作”，Project Tree 负责“这些工作最终归到哪里”。

Project Tree：结构入口

为长期管理优化。项目树不需要承担“最近聊天列表”的职责，尤其是很多项目并不常用。

Agent System active

当前有 3 个活跃 sessions，默认浮到树的顶部或 Starred 区。

Shopify Experiments quiet

无近期 session，折叠在普通项目区。

Archive / Legacy cold

低频项目不占据日常 agent dock，只在搜索和树中出现。

设计规则：最近会话、活跃会话、等待响应优先出现在 Agent Dock；项目树只负责稳定归属。低频项目不会污染日常会话入口。

Agent Dock 不按树默认展开

Dock 的默认排序应是 Recent / Active / Needs input，而不是 Project / Domain / Task。层级只作为每条 session 的轻量标签。

项目归属自动补全

用户从 quick chat 发起任务时，可以先不选项目；系统根据 cwd、文件、标题或用户后续选择自动挂到 project/domain/task。

低频项目沉底

项目树需要 Recent、Starred、Active scopes。没有活跃 session 的项目不要出现在 agent dock 的默认视图里。

工具如何组织工作与 Agent

这些产品的共性不是界面长得像，而是它们都把“工作对象”和“执行者/自动化”分开处理。

Source-informed
Linear Outcome first

Linear 把 project 定义为有明确结果和计划完成时间的工作单元；项目页提供 overview、properties、docs、links、milestones 和 project-specific issue views。

  • 项目是 outcome 容器，不是会话容器。
  • 右侧 details sidebar 用来编辑属性和查看进度。
  • Initiatives 再向上汇总多个 projects 的健康度。
Jira Views + issue detail

Jira 用 backlog、board、timeline、list、calendar、dashboard 等视图处理不同工作节奏；单个 work item 可在 side panel 中查看和配置字段、评论、附件、子项。

  • 主视图负责计划和排序。
  • 侧栏负责当前 issue 的局部信息。
  • 复杂信息被拆到不同视图，不堆在同一栏。
ClickUp Hierarchy

ClickUp 明确把 Workspace、Spaces、Folders、Lists、Tasks、Subtasks 做成层级，并通过侧边栏展开访问。它的重点是位置、权限和可扩展结构。

  • 层级是系统可理解的空间模型。
  • 任务和子任务承载具体执行。
  • 侧边栏适合导航，不适合放所有上下文。
GitHub Copilot Agents Delegation layer

GitHub 把 agent 描述为能在后台研究 repo、制定计划、改代码、跑测试并提交 PR 的异步工作者；用户从 Issue、VS Code、GitHub 页面等入口委派任务。

  • Agent 是后台执行者，不是项目分类法。
  • 关键交互是 delegate、monitor、review、iterate。
  • 透明度通过日志、commit、PR 和 review 流体现。

为什么当前右侧上下文栏会显得杂乱

问题通常不是信息太多，而是信息来自不同心智模型：对象属性、项目资源、agent 运行态、操作入口、日志都挤在同一个视觉层级。

右侧 Context Inspector 应该放什么

它回答“我当前选中的 project/domain/task 是什么，我需要理解什么才能继续工作”。

适合：Brief、目标、验收标准、owner、状态、依赖、相关文件、决策记录、当前对象 activity、相关 agent 摘要。
不适合：全局 session 列表、全部 agent 日志、跨项目 agent 队列、长运行输出、与当前对象无关的提醒。

Session Rail / Agent Dock 应该放什么

它回答“系统里有哪些 agent 正在替我工作，哪些需要我的注意”。

适合：运行/等待/失败计数、当前 scope 的活跃 agent、需要 review 的事项、快速跳转、暂停/恢复/查看详情。
不适合：完整任务资料、项目计划正文、文件列表、过长的操作按钮、所有 session 默认展开。

Session Rail 的三段式交互

常驻并不等于展开，也不等于只做状态灯。更好的做法是：折叠态支持快速回到最近 chat，展开态再做 session 管理。

Collapsed Rail → Scoped Drawer → Session Detail Interaction Flow

1. Collapsed Rail

默认显示最近/活跃/等待响应的 agent 头像或状态点。用户可以一键回到 chat，不必先找项目。

  • 默认按 Recent / Active / Needs input 排序。
  • hover 显示 agent 名称、项目归属和目标。
  • 红/橙状态才主动吸引注意。

2. Scoped Drawer

点击 rail 后展开 session 列表，默认还是最近/活跃优先；用户可切到 task、domain、project 或 all scope。

3. Session Detail

  • 展示完整 logs、files、diff、terminal。
  • 提供 pause、resume、handoff、archive。
  • 与 PM task 双向链接。

推荐落地方案

最终方案不是把 session rail 塞进右侧上下文栏，也不是让项目树接管聊天入口。Agent Dock 放在系统外缘，默认服务快速对话，必要时再切到项目 scope。

信息层级

左侧树保留 Project / Domain / Task；中央显示当前对象的主要工作内容；右侧检查器显示当前对象上下文；最右 rail 显示 agent 状态。

默认排序

Session rail 默认按 Recent / Active / Needs input 排序。当前 project/domain/task 作为过滤器和标签存在，而不是默认把用户锁进树里。

四字段卡片

展开 drawer 后，每个 session 只显示 status、objective、target node、next human action。日志和 diff 不在列表卡片里展示。

入口设计

在 rail 提供 quick chat / continue；在任务标题区提供 Delegate / Attach session；在命令面板提供全局 start agent。

右侧栏改名

把右侧栏从“Context”收敛为 “Brief / Evidence / Activity” 三段，Agent 摘要只是 Activity 的一个 filtered view。

通知策略

只有 blocked、needs review、failed 三类状态允许提升视觉权重。running 状态保持安静，避免不断抢注意力。

可以直接改到现有原型里的版本

如果只做一轮设计实验，我建议先做这些改动，能最快验证“常驻但不 overload”。

  • 把右侧栏顶部 tabs 从 Agents / Files / Plan / Log 改成 Brief / Evidence / Activity，减少不同类型信息抢同一层级。
  • 把 Agents 内容移到 Activity 下的 scoped section，只保留当前 task 相关 agent 摘要。
  • 把最右 session rail 默认压缩到 52px，展示最近/活跃/等待响应的 agent 头像或状态点，不展示完整 session title。
  • 点击 rail 展开 300-340px drawer，drawer 默认按 Recent / Active / Needs input 排序，并提供 Project / Domain / Task 分组切换。
  • 每张 session 卡只留一行动作：Open、Review、Resume 之一，其他操作进详情页。
  • 增加 scope switch：Recent / This task / This domain / This project / All。默认是 Recent，而不是永远跟随当前选择。
